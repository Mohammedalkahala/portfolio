Two loops

The detection loop

A threat-intel bot (CVE Radar) surfaces a new CVE or company report. An AI detection-engineering agent drafts a Wazuh and Sigma rule. I review and edit it, deploy it, then attack it from Kali, Atomic Red Team or Caldera. A grading agent scores PASS or FAIL against the attack, and only then does the rule get committed to GitHub — with its case, its grade and its git history.

The operations loop

Wazuh streams level-10+ alerts to a SOC-triage agent that posts a benign / suspicious / malicious verdict with the evidence it checked. A separate ops agent posts a plain-English health report of the office every morning — the same thing a small-firm client would actually want to see.

The agents

Six agents run the lab: five n8n workflows — detection-engineering, SOC triage, grade & review, finalize & deploy, and a daily ops report — plus the lab-ops agent that builds and changes infrastructure. Each calls a local or hosted model, logs every tool call, and posts to its own Discord channel.

Watching the watcher

The agents are the interesting part and the dangerous part, so they run on a leash. The lab-ops agent reads every machine with no admin rights and makes changes only through approved, logged paths — a firewall-apply helper, a domain-join helper, and an explicit approval prompt for anything sensitive. A root-owned guard hook blocks secret-printing, destructive commands and any attempt to disable logging or firewalls, and every tool call the agent makes is logged to Wazuh. Wazuh has its own rules that alert when the agent acts, when the guard blocks something, and when a firewall change is applied or refused. The watcher is watched.
